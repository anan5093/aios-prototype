## 1. AI Disclosure & Development Philosophy

### 1.1 Transparent AI Use Policy

This project uses **AntiGravity** as an AI-assisted vibe-coding tool for end-to-end code generation. This section exists to be fully transparent about how AI is used, where human judgment takes over, and why this approach still represents genuine engineering work.

> **Core Stance:** AI is a tool. The architecture, the ideas, the debugging, and the validation are mine. I understand every system I build.

---

### 1.2 What AI Does in This Project

| AI Responsibility | Details |
|---|---|
| **Boilerplate scaffolding** | Generating repetitive setup code: Express routes, React component skeletons, Pydantic models, package.json configs |
| **First-draft implementations** | Initial version of modules like `faiss_store.py`, `atlas_store.py`, `sanitiser.py` based on precise prompts I author |
| **Syntax and pattern lookup** | Replacing Stack Overflow for things like "asyncio.gather with timeout", "MongoDB $vectorSearch aggregation syntax" |
| **Refactoring suggestions** | Proposing cleaner structures after I identify a design smell during manual testing |
| **Documentation drafting** | First-pass docstrings and inline comments that I then review and correct |

---

### 1.3 What I Own — Human-in-the-Loop Engineering

The following are **never delegated to AI**. These are where my technical knowledge and original thinking drive the project:

| My Responsibility | Why It Cannot Be Delegated |
|---|---|
| **System architecture decisions** | The choice to use FAISS + Atlas hybrid retrieval, the circuit-breaker pattern, the Intent-Validate-Execute pipeline — these came from my own architectural thinking, not from AI suggestions. |
| **Debugging all AI-generated code** | Every module generated by AntiGravity is read line-by-line, run locally, and verified against expected behaviour before being committed. I use `pdb`, `pytest`, and manual `curl`/`wscat` tests to confirm correctness. |
| **Integration testing across components** | I manually verify that the daemon correctly connects to Atlas, that the FAISS retrieval actually returns relevant chunks, that the circuit breaker truly falls back, and that the WebSocket stream reaches the React dashboard. |
| **Security review of outbound payloads** | I personally inspect sanitised payloads using a local proxy (mitmproxy) to confirm PII is stripped before transmission. This is not something I trust to AI to verify. |
| **Prompt engineering for the LLM** | The system role prompt, the XML context block format, and the JSON intent schema are authored and iterated by me. I test each prompt version against 10+ adversarial inputs. |
| **Ethical constraint enforcement** | The decision that no intent auto-executes without human approval is a design principle I hold, not a feature I asked AI to implement. I verify this works by attempting to bypass it in code. |
| **Performance tuning** | RAM profiling (memory_profiler), latency measurement, and FAISS index size tuning are done manually on my actual hardware. AI cannot know what 7.74 GB of usable RAM feels like under load. |
| **Capstone report and documentation** | All technical writing, diagrams, and explanations represent my own understanding. AI-drafted text is heavily revised or rewritten in my own voice. |

### [T1-03] Build Persistent Kaggle Inference Server + ngrok Static Tunnel 🔴 MUST

**Goal:** Create a Kaggle notebook that reliably serves quantised LLM inference via Ollama with full GPU acceleration, exposed through a **permanent ngrok static domain** — eliminating the URL re-discovery problem present in Colab-based approaches.

**Why Kaggle over Colab:**
- 30 GPU hours/week free (vs Colab's unpredictable 15–30)
- Background execution — session stays alive when browser tab is closed (no keep-alive loops)
- 20 GB persistent storage — Ollama model weights cached across sessions (no re-download)
- Static ngrok domain — URL never changes, even across session restarts

**Inputs:** Kaggle account (free), ngrok account (free), `.env.example` from T1-01.

**Pre-step — Get Your ngrok Static Domain:**
1. Go to [dashboard.ngrok.com/domains](https://dashboard.ngrok.com/domains)
2. Click "New Domain" → Kaggle gives you a free static subdomain like `your-name.ngrok-free.app`
3. Copy the domain and your auth token — both go into `.env`

**Steps:**
1. On Kaggle, create a new notebook named `aios-inference-server`. In Settings: set **Accelerator → GPU T4 ×1** (or P100 if available). Enable **"Persistence → Files & Variables"** (this is what enables background execution).

2. Create `scripts/aios_kaggle_server.ipynb` with these cells:

   **Cell 1 — Configure CUDA & Install Ollama:**
   ```python
   import os, subprocess, time

   # Configure full GPU offload for Ollama
   os.environ['CUDA_HOME'] = '/usr/local/cuda'
   os.environ['OLLAMA_GPU_LAYERS'] = '100'    # all layers on GPU
   os.environ['OLLAMA_SCHED_SPREAD'] = '1'    # spread across both T4s if 2×

   subprocess.run(
       "curl -fsSL https://ollama.com/install.sh | sh",
       shell=True, check=True
   )
   print("✅ Ollama installed")
   ```

   **Cell 2 — Start Server & Pull Model (cached after first run):**
   ```python
   # Start Ollama server in background
   subprocess.Popen(["ollama", "serve"],
                    stdout=subprocess.DEVNULL,
                    stderr=subprocess.DEVNULL)
   time.sleep(4)

   # Model weights cached in /kaggle/working/ — only downloads once
   subprocess.run(["ollama", "pull", "gemma:2b-instruct-q4_K_M"], check=True)

   # Upgrade option: P100 or T4×2 users can run 8B
   # subprocess.run(["ollama", "pull", "llama3:8b-instruct-q4_K_M"], check=True)

   print("✅ Model ready")
   subprocess.run(["ollama", "ps"])  # confirm model loaded on GPU
   ```

   **Cell 3 — Open ngrok Tunnel with Static Domain:**
   ```python
   subprocess.run(["pip", "install", "pyngrok", "-q"], check=True)
   from pyngrok import ngrok, conf

   NGROK_AUTH_TOKEN   = "YOUR_NGROK_AUTH_TOKEN"       # from ngrok dashboard
   NGROK_STATIC_DOMAIN = "your-name.ngrok-free.app"   # your free static domain
   BASIC_AUTH_USER    = "aios"
   BASIC_AUTH_PASS    = "your_strong_password"         # match .env

   conf.get_default().auth_token = NGROK_AUTH_TOKEN

   tunnel = ngrok.connect(
       addr=11434,
       bind_tls=True,
       domain=NGROK_STATIC_DOMAIN,   # static — survives session restarts
       auth=f"{BASIC_AUTH_USER}:{BASIC_AUTH_PASS}"
   )
   print(f"✅ Endpoint: {tunnel.public_url}")
   print(f"   Test: curl -u {BASIC_AUTH_USER}:{BASIC_AUTH_PASS} {tunnel.public_url}/api/tags")
   # Write URL to file (same every time — just confirms tunnel is live)
   with open("/kaggle/working/ngrok_url.txt", "w") as f:
       f.write(tunnel.public_url)
   ```

   **Cell 4 — Health Log (lightweight, background execution handles keep-alive):**
   ```python
   # With "Persistence → Files & Variables" enabled in Kaggle settings,
   # you can close this browser tab — the session keeps running.
   print("🟢 Server running. Safe to close browser tab.")
   while True:
       result = subprocess.run(["ollama", "ps"], capture_output=True, text=True)
       print(f"[{time.strftime('%H:%M:%S')}] {result.stdout.strip() or 'idle'}")
       time.sleep(120)
   ```

3. In `.env`, set the static domain permanently:
   ```
   OLLAMA_ENDPOINT=https://your-name.ngrok-free.app
   NGROK_AUTH_USER=aios
   NGROK_AUTH_PASS=your_strong_password
   NGROK_STATIC_DOMAIN=your-name.ngrok-free.app
   ```
   Note: this URL **never changes** — no URL discovery file, no polling.

4. Test the endpoint from local terminal:
   ```bash
   curl -u aios:your_strong_password https://your-name.ngrok-free.app/api/tags
   curl -u aios:your_strong_password -X POST \
     https://your-name.ngrok-free.app/api/generate \
     -d '{"model":"gemma:2b-instruct-q4_K_M","prompt":"Hello, AIOS!","stream":false}'
   ```

**AI Usage:**
- AntiGravity: generates the notebook cell structure.
- Me: supply actual ngrok token and static domain; run each cell manually and observe GPU allocation with `nvidia-smi` output; test the endpoint with `curl` and verify Basic Auth rejects requests without credentials; confirm `ollama ps` shows the model loaded on GPU (not CPU); document GPU tier in README so the model selection (`MODEL_NAME` in `.env`) is clear.

**Acceptance Criteria:**
- [ ] `curl -u aios:PASSWORD https://your-name.ngrok-free.app/api/tags` returns JSON model list.
- [ ] A test generation request returns a valid completion JSON with a non-empty `response` field.
